Try first

Sample data is built in

Each program starts by making fake data with known problems planted in it. Run it unchanged first to see what the flags look like, then swap in your own data (section 3).

01

Volume deviation monitor

For each day, week or month, the program works out what normal looks like from recent history, then flags anything more than k standard deviations away from it.

The idea

A rolling expected range

The shaded band is the mean ± k SD of the previous periods. The current day isn't part of its own baseline, so a spike can't raise the bar it's measured against.

HIGHLOWOKWARMUP WARMUP means there isn't enough history to judge yet.
Weekdays

Mondays vs Mondays

Mon–Sat each get their own baseline made of the same weekday only. By default that's the last 56 days, so 8 earlier Mondays for a Monday. A quiet Saturday is judged against other Saturdays, so it isn't flagged LOW for being lower than a Tuesday.

Sundays

Should be zero

Every past Sunday is 0, so the SD is 0 and the standard deviation check can't work on them. Instead, any Sunday with volume above 0 is flagged SUNDAY and listed in its own report.

Bank holidays

Taken out of the check

Dates in the holidays table are left out, so a closed Monday isn't flagged LOW and doesn't drag down the baseline for later Mondays. Add your own closure days to it.

Weekly view

Weeks start on Monday

Daily volumes are added up into Monday-to-Sunday weeks with intnx('week.2', …), and each week is labelled with its Monday's date. By default each week is checked against the previous 12. Every week has a weekend, so no adjustment is needed.

How you run it

Set the dates, then one call for everything

Set the date range at the top of the program, then use the %volume_check calls at the bottom. period=ALL runs day, week and month in one call. Give one baseline for all three, or one each in the same order.

%let start_date = 01JAN2025;     /* blank = from the start of the file */
%let end_date   = 30JUN2026;     /* blank = to the end of the file     */

/* Everything in one go */
%volume_check(period=ALL, baseline=90D | 26W | 12M,
              views=ALL | product | channel | product channel);

/* Or one period at a time */
%volume_check(period=DAY,   baseline=90D, views=ALL | product);
%volume_check(period=MONTH, baseline=12M, views=ALL, tables=N);

%flag_summary;

Output

What each check gives you

1Key observations

The urgent call-outs. Flagged periods only, worst first, with the volume, the expected value and range, % vs expected, and z-score. If there's nothing to report, it says so.

2Chart per group

Volume against the shaded expected range, with markers on HIGH and LOW periods.

3Full table

Every day, week or month, with HIGH rows in red, LOW rows in purple and WARMUP rows greyed out.

4Run summary

Every call-out from the whole run, most recent first, plus counts by period, view and group. All of it is also kept in WORK.ALL_FLAGS.

Date range

Leave room for the baseline

The date range filters everything, baselines included. If you start on 1 March with a 90D baseline, early March has no history to compare with and shows as WARMUP. Start around 90 days before the dates you care about.

Write dates like 01JAN2025. Anything else is reported as an ERROR in the log, and that limit is ignored.

Output size

Everything can mean a lot of output

With all three periods and four views, that's dozens of charts and some long daily tables. For a quick look, set charts=N tables=N and use the key observations and run summary.

Baseline

All history, or a rolling span

ALL uses every earlier period in the file, so the baseline grows over time. A rolling span uses only the most recent history before each date and moves forward with it.

  • 90D suits daily checks: about 13 earlier Mondays for a Monday
  • 26W suits weekly checks
  • 12M or 2Y suits monthly checks

Choose rolling if volumes drift, so you aren't comparing with an old normal. Match the span to the period: 90D gives a monthly check only about 3 months, which is below min_obs, so nothing would ever be flagged.

Views

Everything, by product, by channel, or both

In views=Checks
ALLStraight totals
productEach product against its own history
channelEach channel against its own history
product channelEach combination, such as Cards/Phone

Each call can use different views. For example, you could check days by product and channel but months as totals only.

Good to know

Groups and missing days

  • Missing days count as 0. If a group has no records on a day, that day is filled in as 0, so it can still be flagged LOW.
  • Small groups are noisy. Combinations with only a handful of items a day will flag often, so use a broader view or raise k to 3.
  • One problem can show up in several views. A Cards/Phone spike may also show in Cards, in Phone and in the totals. The finest view that flags it tells you where it came from.
Monthly view

Average per open day

Months have different numbers of working days and bank holidays, so comparing raw totals would flag short months as LOW. The program divides each month's total by its open days (Mon–Sat, not a bank holiday) and by default checks that average against the previous 12 months.

The report shows the total, the number of open days and the average, so you can see which one moved. The calendar is built from dates, so a day with no records still counts as an open day.

Monthly view

Needs at least 6 months of history

Nothing is flagged until a month has 6 earlier months to compare with. With the default 12M baseline, give it at least 18 months of data. Seasonal months such as December may flag every year. A 12-month baseline softens that but doesn't remove it.

Settings

Settings at the top

Good to know

When volumes shift for good

If volumes permanently go up or down, you'll get a run of flags until the look-back window catches up. That's usually useful, because the run itself tells you something changed.

/*====================================================================
  VOLUME DEVIATION MONITOR                       Base SAS 9.4 / EG
  ====================================================================
  WHAT IT DOES
  Spots days, weeks and months where volume is unusually high or low.
  For each period it works out "normal" from a baseline of EARLIER
  periods (their mean and standard deviation) and flags anything more
  than K standard deviations away. A period is never part of its own
  baseline, so a spike can't hide by raising the bar.

  HOW TO RUN IT
  1. Step 0: replace the sample data with your own table (keep the
     column names DATE and VOLUME - see INPUT DATA below), or run the
     sample first to see what the output looks like.
  2. Set K, START_DATE and END_DATE just below this box.
  3. Add your bank holidays in step 1 if your data goes beyond 2026.
  4. Edit the %volume_check calls in step 4 (the bottom of the program).
  5. Run the whole program (F3 in Enterprise Guide).

  ====================================================================
  QUICK REFERENCE - every setting and argument
  ====================================================================

  SETTINGS AT THE TOP (apply to every check)
  ------------------------------------------
  k           How many standard deviations from normal counts as unusual.
                2    sensitive: about 1 in 20 normal periods gets flagged
                2.5  middle ground
                3    strong signals only: about 1 in 370 normal periods
              Default 2. Decimals are fine.

  start_date  Ignore data before this date. Write it like 01JAN2025.
              Blank = from the start of the file.
  end_date    Ignore data after this date. Write it like 30JUN2026.
              Blank = to the end of the file.
              NB the date range limits the baseline history too, so start
              about one baseline-length before the dates you care about.

  INPUT DATA (step 0) - must end up as table WORK.RAW
  ---------------------------------------------------
  date        Numeric SAS date. If yours is a date-time (e.g.
              02NOV2026:09:15:00) use  date = datepart(your_column);
  volume      Numeric. If each row is one item, use  volume = 1;
  <groups>    Optional extra columns to split by (product, channel, team...).
              Keep their own names and use them in views= .

  BANK HOLIDAYS (step 1) - table WORK.HOLIDAYS
  --------------------------------------------
  One date per line, like 25DEC2026. These days are left out of the
  daily check (so they don't flag as LOW) and don't count as open days
  in the monthly check. England & Wales 2025-26 are filled in.

  %volume_check( period=, baseline=, views=, min_obs=, charts=, tables= )
  -----------------------------------------------------------------------
  period=    REQUIRED. Which period(s) to check.
               DAY    each Mon-Sat day vs the SAME weekday (Mondays vs
                      Mondays...), plus a check that Sundays are zero
               WEEK   Monday-to-Sunday weeks, labelled by the Monday
               MONTH  calendar months, compared as AVERAGE PER OPEN DAY
                      (open day = Mon-Sat, not a bank holiday) so short
                      months don't look low
               ALL    all three - same as  DAY | WEEK | MONTH
             You can list several, separated by | , e.g.  DAY | WEEK
             DAILY / WEEKLY / MONTHLY are accepted too.

  baseline=  How much EARLIER history counts as "normal".
               ALL    every earlier period in the date range
                      (the baseline grows as time goes on)
               90D    the previous 90 days    (any number + D)
               26W    the previous 26 weeks   (any number + W)
               12M    the previous 12 months  (any number + M)
               2Y     the previous 2 years    (any number + Y)
             One value is used for every period in period=.
             A list gives one per period, in the same order:
               period=ALL, baseline=90D | 26W | 12M
             Blank = 56D for DAY, 12W for WEEK, 12M for MONTH.
             Tip: match the span to the period. 90D is plenty for DAY
             (about 13 earlier Mondays) but gives MONTH only ~3 months.
             Use a rolling span if volumes drift over time; use ALL if
             they're stable and you want the steadiest baseline.

  views=     Which splits to run, separated by | . Each view is checked
             separately, with its own baseline for every group in it.
               ALL               straight totals (everything together)
               product           each product vs its own history
               channel           each channel vs its own history
               product channel   each product/channel combination
             Use any column names from your data (max two per view is
             sensible - small groups are noisy). Blank = ALL.

  min_obs=   How many earlier periods the baseline must contain before
             anything can be flagged. Until then the period shows WARMUP.
             One value, or one per period in the same order:  4 | 6 | 6
             Blank = 4 for DAY, 6 for WEEK and MONTH. Minimum sensible: 3.

  charts=    Y  a chart per group: volume vs the shaded expected range,
                with markers on flagged periods                (default)
             N  no charts

  tables=    Y  a full table of every period, HIGH rows red, LOW rows
                purple, WARMUP rows grey                       (default)
             N  no full tables

  The KEY OBSERVATIONS table (flagged periods, worst first) is always
  printed - those are the urgent call-outs.

  EXAMPLES
    %volume_check(period=ALL);
        day, week and month with default baselines, totals only
    %volume_check(period=ALL, baseline=ALL);
        all three, each compared with all earlier history
    %volume_check(period=ALL, baseline=90D | 26W | 12M,
                  views=ALL | product | channel | product channel);
        the lot: every period, every view
    %volume_check(period=DAY, baseline=90D, views=product, charts=N);
        daily by product, no charts
    %volume_check(period=WEEK | MONTH, baseline=ALL, tables=N, min_obs=8);
        weeks and months vs all history, need 8 periods before flagging

  %flag_summary;
  --------------
  No arguments. Run it once after your %volume_check calls. Prints every
  call-out from the whole run (most recent first) and a count of HIGH,
  LOW and SUNDAY flags by period, view and group.

  WHAT THE FLAGS MEAN
  -------------------
  HIGH     above the expected range (mean + k x SD)
  LOW      below the expected range (mean - k x SD)
  SUNDAY   volume on a Sunday - Sundays should be zero
  OK       inside the expected range
  WARMUP   not enough earlier periods yet to judge (see min_obs=)

  COLUMNS IN THE OUTPUT
  ---------------------
  Expected        mean of the baseline
  Expected low    mean - k x SD (shown as 0 if it would be negative)
  Expected high   mean + k x SD
  vs expected     % difference from the expected value
  z-score         how many SDs from expected (+ above, - below)
  Periods in baseline   how many earlier periods the baseline used

  OUTPUT TABLES (in WORK - open them in EG to sort and filter)
  ------------------------------------------------------------
  ALL_FLAGS       every call-out from every check in this run, with
                  period_type, baseline, level (the view), group_name,
                  date, volume, mean, lower, upper, pct_diff, z,
                  severity (size of z), baseline_n and flag.
                  Emptied at the start of each run.
  DAILY_FLAGS     every period with its expected range, for the LAST
  WEEKLY_FLAGS    view run of each period - handy for checking one
  MONTHLY_FLAGS   group in detail.
====================================================================*/

     One row per day per product per channel, with a VOLUME.

/* TO USE YOUR OWN DATA: delete the sample step below and use this
   instead (or build it with the Column mapper on the toolkit page).

data raw;
  set mylib.my_table;                 <- your library.table
  date   = datepart(created_dt);      <- your date column (drop datepart()
                                         if it's already a date)
  volume = 1;                         <- 1 per row, or your count column
  format date date9.;
  keep date volume product channel;   <- add your group columns here
run;

data raw;
  call streaminit(42);
  length product $10 channel $6;
  array prod[3] $10 _temporary_ ('Cards', 'Loans', 'Mortgages');
  array base[3]     _temporary_ (500, 300, 200);
  array chan[2] $6  _temporary_ ('Phone', 'Online');
  array share[2]    _temporary_ (0.4, 0.6);

  do date = '01JAN2025'd to '30JUN2026'd;       /* 18 months of history */
    select (weekday(date));                       /* 1=Sun ... 7=Sat */
      when (1)  dayfactor = 0;                    /* Sunday: closed  */
      when (7)  dayfactor = 0.3;                  /* quiet Saturday  */
      otherwise dayfactor = 1;
    end;
    if '01APR2026'd <= date <= '30APR2026'd then
      dayfactor = dayfactor * 1.15;               /* planted busy month */

    do p = 1 to 3;
      do c = 1 to 2;
        product = prod[p];
        channel = chan[c];
        expected = base[p] * share[c] * dayfactor;
        if expected > 0 then volume = rand('poisson', expected);
        else volume = 0;

        /* planted problems */
        if date = '17MAR2026'd and product = 'Cards' and channel = 'Phone'
          then volume = volume + 400;             /* spike */
        if date = '02MAY2026'd and product = 'Loans' and channel = 'Online'
          then volume = round(volume * 0.2);      /* drop  */
        if date = '15MAR2026'd and product = 'Mortgages' and channel = 'Online'
          then volume = 40;                       /* Sunday activity */
        output;
      end;
    end;
  end;
  format date date9.;
  keep date product channel volume;
run;

/*--------------------------------------------------------------------
  2. Flagging macro (used by %volume_check - no need to call directly)
     Baseline uses ONLY earlier periods, so a value can't hide itself
     by inflating its own mean/SD.
     SPAN= ALL (everything earlier) or a rolling span like 90D/26W/12M.
     BY= runs a separate baseline per group.
--------------------------------------------------------------------*/
%macro _span_ok(span);
  %local s u nb;
  %let s = %upcase(&span);
  %if &s = ALL %then 1;
  %else %if %length(&s) < 2 %then 0;
  %else %do;
    %let u  = %substr(&s, %length(&s));
    %let nb = %substr(&s, 1, %eval(%length(&s) - 1));
    %if %sysfunc(notdigit(&nb)) %then 0;
    %else %if &u = D or &u = W or &u = M or &u = Y %then 1;
    %else 0;
  %end;
%mend _span_ok;

%macro flag_deviations(in=, out=, span=ALL, min_obs=4, kval=2, by=);
  %local mode nback unit interval cap;
  %let cap  = 5000;                        /* max earlier periods held per group */
  %let span = %upcase(&span);

  %if &span = ALL %then %let mode = ALL;
  %else %do;
    %let mode  = SPAN;
    %let unit  = %substr(&span, %length(&span));
    %let nback = %substr(&span, 1, %eval(%length(&span) - 1));
    %if &unit = D %then %let interval = day;
    %else %if &unit = W %then %let interval = week;
    %else %if &unit = M %then %let interval = month;
    %else %let interval = year;
  %end;

  proc sort data=&in out=_srt; by &by date; run;

  data &out;
    set _srt;
    by &by date;
    length flag $6 baseline $8;
    baseline = "&span";

  %if &mode = ALL %then %do;
    /* Expanding baseline: running totals of everything earlier */
    retain cnt s ss 0;
    if first.%scan(&by, -1) then do;
      cnt = 0; s = 0; ss = 0;
    end;
  %end;
  %else %do;
    /* Rolling baseline: earlier periods with a date inside the span */
    array bd[&cap] _temporary_;            /* dates of earlier periods   */
    array bv[&cap] _temporary_;            /* volumes of earlier periods */
    retain n 0;
    if first.%scan(&by, -1) then n = 0;

    cnt = 0; s = 0; ss = 0;
    cutoff = intnx("&interval", date, -&nback, 's');
    do j = 0 to min(n, &cap) - 1;          /* newest first, stop when too old */
      idx = mod(n - 1 - j, &cap) + 1;
      if bd[idx] < cutoff then leave;
      cnt = cnt + 1;
      s   = s + bv[idx];
      ss  = ss + bv[idx]**2;
    end;
  %end;

    baseline_n = cnt;                      /* earlier periods in the baseline */
    if cnt >= &min_obs then do;
      mean  = s / cnt;
      sd    = sqrt(max(0, (ss - cnt*mean**2) / (cnt - 1)));
      lower = max(0, mean - &kval*sd);
      upper = mean + &kval*sd;
      if sd > 0 then do;
        z = (volume - mean) / sd;
        severity = abs(z);
      end;
      if mean > 0 then pct_diff = (volume - mean) / mean;
      if      volume > upper then flag = 'HIGH';
      else if volume < mean - &kval*sd then flag = 'LOW';
      else                        flag = 'OK';
    end;
    else flag = 'WARMUP';

    /* add this period so later rows can use it */
  %if &mode = ALL %then %do;
    cnt = cnt + 1;
    s   = s + volume;
    ss  = ss + volume**2;
    drop cnt s ss;
  %end;
  %else %do;
    n = n + 1;
    idx = mod(n - 1, &cap) + 1;
    bd[idx] = date;
    bv[idx] = volume;
    drop n j idx cnt s ss cutoff;
  %end;

    format mean sd lower upper comma12.1 z 6.2 pct_diff percentn8.1;
    label baseline = 'Baseline' baseline_n = 'Periods in baseline'
          mean = 'Expected' lower = 'Expected low' upper = 'Expected high'
          pct_diff = 'vs expected' z = 'z-score' flag = 'Flag';
  run;

%mend flag_deviations;

/*--------------------------------------------------------------------
  3. One period, one view (used by %volume_check)
--------------------------------------------------------------------*/
%macro _check_view(period=, baseline=, min_obs=, groups=, view_no=, charts=, tables=);
  %local grp gcomma showgrp label res plabel pnoun period_no nkey;

  %if %length(&groups) = 0 %then %do;
    %let grp     = _all_;
    %let gcomma  = _all_;
    %let showgrp = ;
    %let label   = Everything;
  %end;
  %else %do;
    %let grp     = %sysfunc(compbl(&groups));
    %let gcomma  = %unquote(%sysfunc(translate(&grp, %str(,), %str( ))));
    %let showgrp = &grp;
    %let label   = By &grp;
  %end;

  /* Daily totals per group, with zero-filled gaps */
  proc sql;
    create table _daily_raw as
    select &gcomma, date, sum(volume) as volume
    from raw_g
    group by &gcomma, date;

    create table _groups as
    select distinct &gcomma from raw_g;

    create table _grid as
    select * from _groups, _dates;

    create table daily as
    select * from _grid natural left join _daily_raw
    order by &gcomma, date;
  quit;

  data daily;
    set daily;
    if missing(volume) then volume = 0;
  run;

  %if &period = DAY %then %do;
    %let res = daily_flags;  %let plabel = Daily;   %let period_no = 1;
    %let pnoun = days (each weekday vs the same weekday);

    /* Sundays should be zero; Mon-Sat checked vs the same weekday */
    proc sql;
      create table daily_dow as
      select d.*, weekday(d.date) as dow
      from daily d
      where d.date not in (select date from holidays);
    quit;

    data sunday_check open_days;
      set daily_dow;
      length flag $6;
      if dow = 1 then do;
        if volume > 0 then flag = 'SUNDAY';
        else flag = 'OK';
        output sunday_check;
      end;
      else output open_days;
    run;

    %flag_deviations(in=open_days, out=daily_flags, span=&baseline, min_obs=&min_obs,
                     kval=&k, by=&grp dow);
    proc sort data=daily_flags; by &grp date; run;
  %end;

  %else %if &period = WEEK %then %do;
    %let res = weekly_flags; %let plabel = Weekly;  %let period_no = 2;
    %let pnoun = weeks (Monday to Sunday);

    data _wk;
      set daily(rename=(date=day));
      wk = intnx('week.2', day, 0, 'b');
    run;

    proc sql;
      create table weekly as
      select &gcomma, wk as date format=date9., sum(volume) as volume
      from _wk
      group by &gcomma, wk
      order by &gcomma, date;
    quit;

    %flag_deviations(in=weekly, out=weekly_flags, span=&baseline, min_obs=&min_obs,
                     kval=&k, by=&grp);
  %end;

  %else %do;
    %let res = monthly_flags; %let plabel = Monthly; %let period_no = 3;
    %let pnoun = months (average per open day);

      set daily(rename=(date=day));

/*--------------------------------------------------------------------
  The macro you call:
    period   = DAY, WEEK, MONTH, a list such as DAY | WEEK,
               or ALL (= DAY | WEEK | MONTH)                    (required)
    baseline = ALL, or a rolling span: 90D, 26W, 12M, 2Y ...
               One value applies to every period; or give one per
               period in the same order, e.g. 90D | 26W | 12M.
               Blank = 56D for DAY, 12W for WEEK, 12M for MONTH.
    views    = splits to run, separated by |                    (blank = ALL)
               ALL | product | channel | product channel
    min_obs  = earlier periods needed before anything is flagged.
               One value, or one per period. Blank = 4 / 6 / 6.
    charts   = Y/N  chart per group                             (default Y)
    tables   = Y/N  full table of every period                  (default Y)
  Key observations are always printed.
--------------------------------------------------------------------*/
%macro volume_check(period=, baseline=, views=, min_obs=, charts=Y, tables=Y);
  %local plist np nb nm j p b m i n lvl;

  %let plist = %upcase(&period);
  %if &plist = ALL %then %let plist = DAY | WEEK | MONTH;
  %if %length(&plist) = 0 %then %do;
    %put ERROR: volume_check: period= is required (DAY, WEEK, MONTH or ALL).;
    %return;
  %end;
  %let np = %sysfunc(countw(&plist, |));

  %let nb = 0;
  %if %length(&baseline) %then %let nb = %sysfunc(countw(&baseline, |));
  %if &nb > 1 and &nb ne &np %then %do;
    %put ERROR: volume_check: give one baseline, or one per period (&np periods, &nb baselines).;
    %return;
  %end;

  %let nm = 0;
  %if %length(&min_obs) %then %let nm = %sysfunc(countw(&min_obs, |));
  %if &nm > 1 and &nm ne &np %then %do;
    %put ERROR: volume_check: give one min_obs, or one per period (&np periods, &nm values).;
    %return;
  %end;

  %if %length(&views) = 0 %then %let views = ALL;

  %do j = 1 %to &np;
    /* which period */
    %let p = %scan(&plist, &j, |);
    %if &p = DAILY   %then %let p = DAY;
    %if &p = WEEKLY  %then %let p = WEEK;
    %if &p = MONTHLY %then %let p = MONTH;
    %if &p ne DAY and &p ne WEEK and &p ne MONTH %then %do;
      %put ERROR: volume_check: period "&p" not recognised - use DAY, WEEK, MONTH or ALL.;
      %return;
    %end;

    /* which baseline */
    %if &nb = 0 %then %do;
      %if &p = DAY %then %let b = 56D;
      %else %if &p = WEEK %then %let b = 12W;
      %else %let b = 12M;
    %end;
    %else %if &nb = 1 %then %let b = &baseline;
    %else %let b = %scan(&baseline, &j, |);
    %let b = %upcase(%sysfunc(compress(&b)));
    %if %_span_ok(&b) = 0 %then %do;
      %put ERROR: volume_check: baseline "&b" not recognised - use ALL, or a number followed by D, W, M or Y (e.g. 90D).;
      %return;
    %end;

    /* how much history before flagging */
    %if &nm = 0 %then %do;
      %if &p = DAY %then %let m = 4;
      %else %let m = 6;
    %end;
    %else %if &nm = 1 %then %let m = %sysfunc(compress(&min_obs));
    %else %let m = %sysfunc(compress(%scan(&min_obs, &j, |)));

    /* run each view */
    %let n = %sysfunc(countw(&views, |));
    %do i = 1 %to &n;
      %let lvl = %scan(&views, &i, |);
      %if %upcase(&lvl) = ALL %then %do;
        %_check_view(period=&p, baseline=&b, min_obs=&m, groups=,
                     view_no=&i, charts=&charts, tables=&tables)
      %end;
      %else %do;
        %_check_view(period=&p, baseline=&b, min_obs=&m, groups=&lvl,
                     view_no=&i, charts=&charts, tables=&tables)
      %end;
    %end;
  %end;
%mend volume_check;

Rising keywords in free text

The program splits comments into words and two-word phrases and removes stop words. It then compares how often each term appears in the last 4 weeks with the 12 weeks before, and flags the ones that have gone up significantly.

Step 1

Clean and split the text

The text is made lowercase and stripped of punctuation and numbers. Stop words are removed, then the words that are left are paired up into phrases.

"My card was declined!"→ carddeclinedcard declined

Phrases are paired up after stop words are removed, so "card was declined" becomes the phrase "card declined".

Step 2

Count comments, not words

Each week, it counts how many comments mention a term and works that out as a share of all comments that week. One long rant can't push a word up, and a busy week doesn't make every word look like it's rising.

Step 3

Recent vs baseline

A two-proportion z-test asks whether the recent share is really higher than the baseline share, or just chance.

z = (precent − pbase) / √( p(1−p)(1/nrecent + 1/nbase) )
Step 4

Flag and chart

NEWnot seen in the baseline at all
RISINGsignificantly more common, with a lift such as 3.2×
FALLINGsignificantly less common

The top rising terms are charted week by week, with a dashed line where the recent period starts.

Settings

Choices at the top of the program

SettingDefaultWhat it changes
recent_weeks4How many weeks count as "now".
baseline_weeks12How many weeks before that count as normal.
z_cut3The significance bar. You're testing thousands of terms at once, so a bar of 2 flags plenty by pure chance.
min_docs10The fewest recent mentions a term needs before it can be flagged. Stops one-off typos showing up as trends.
min_len3Drops very short tokens.
top_n6How many rising terms the chart shows.
Tune this first

Add your own stop words

Words that appear in nearly every comment in your data, such as customer, account, bank, complaint, please, will take up space in the results. Add them to the stopwords list.

"not" and "no" are deliberately kept, because "not arrived" carries meaning.

Known limit

Word forms are counted separately

"crash", "crashed" and "crashing" are three different words to this program. If that splits a signal, a small lookup table that maps word forms to one root fixes it.

Partial weeks

Shares, not counts

Because it compares shares, an unfinished current week won't look like a drop. But a week with very few comments will give noisy results.

/*====================================================================
  RISING KEYWORDS IN FREE TEXT                   Base SAS 9.4 / EG
  ====================================================================
  WHAT IT DOES
  Finds words and two-word phrases that people have suddenly started
  using more (or less) in free-text comments.
  1. Cleans the text (lowercase, no punctuation or numbers) and splits
     it into words and two-word phrases, after removing stop words.
  2. Counts how many RECORDS mention each term per week - so one long
     rant can't dominate, and busy weeks don't inflate every word.
  3. Compares the share of records mentioning each term in the RECENT
     weeks with the BASELINE weeks just before (two-proportion z-test).
  4. Lists and charts the terms that have changed significantly.

  HOW TO RUN IT
  1. Step 0: replace the sample data with your own table (see INPUT
     DATA below), or run the sample first to see the output.
  2. Adjust the settings just below this box.
  3. Add words that appear everywhere in YOUR data to the stop words
     in step 1 (e.g. customer, account, complaint, please).
  4. Run the whole program (F3 in Enterprise Guide).

  ====================================================================
  QUICK REFERENCE - every setting
  ====================================================================

  recent_weeks    How many weeks count as "now". The recent period always
                  ENDS at the latest week in the data (weeks run Monday to
                  Sunday). Default 4.

  baseline_weeks  How many weeks just BEFORE the recent period count as
                  "normal". Default 12. More weeks = steadier baseline,
                  but slower to adapt if the normal mix changes.

  z_cut           How strong a change must be to be flagged (z-score).
                  You're testing thousands of terms at once, so keep this
                  high: 2 flags lots by pure chance, 3 is a sensible
                  default, 4 shows only the strongest changes.

  min_docs        A term needs at least this many recent records to be
                  flagged RISING or NEW (and this many baseline records to
                  be flagged FALLING). Stops one-off typos showing up as
                  trends. Default 10. Raise it for big data sets.

  min_len         Words shorter than this are dropped. Default 3
                  (drops "i", "a", "my", "to"...).

  top_n           How many of the top rising terms appear in the weekly
                  trend chart. Default 6.

  INPUT DATA (step 0) - must end up as table WORK.RAW_TEXT
  --------------------------------------------------------
  id     Unique per record (numeric or text). Used so a record that
         mentions a word twice still counts once.
  date   Numeric SAS date. If yours is a date-time use
         date = datepart(your_column);
  text   The free text (character). Default length 300 - if your
         comments are longer, raise  length text $300  in step 0 AND
         length clean $600  in step 2 (make clean about double).

  STOP WORDS (step 1) - table WORK.STOPWORDS
  ------------------------------------------
  Words to ignore, separated by spaces, between "datalines;" and ";".
  Lowercase, no apostrophes (write dont, not don't). "not" and "no" are
  deliberately kept because "not arrived" carries meaning.

  WHAT THE FLAGS MEAN
  -------------------
  NEW       appears in the recent weeks but not at all in the baseline
  RISING    significantly more common recently than in the baseline
  FALLING   significantly less common recently
  (blank)   no significant change

  COLUMNS IN THE OUTPUT (table WORK.RISING)
  -----------------------------------------
  term              the word or two-word phrase
  type              word or phrase
  Recent mentions   records mentioning it in the recent weeks   (x1)
  Recent share      as a % of all records in the recent weeks
  Baseline mentions records mentioning it in the baseline weeks (x0)
  Baseline share    as a % of all records in the baseline weeks
  lift              recent share / baseline share (3.0 = 3x as common)
  z                 strength of the change (+ rising, - falling)
  flag              NEW / RISING / FALLING

  OTHER OUTPUT TABLES (in WORK)
  -----------------------------
  TOKENS      one row per record per term - handy to find example
              comments:  proc print data=tokens; where term='face id'; run;
  TERM_WEEK   records mentioning each term, per week
  TREND       weekly share for the charted terms
====================================================================*/

/*--------------------------------------------------------------------
  2. Tokenise: one row per record per term (words + two-word phrases)
--------------------------------------------------------------------*/
data tokens;
  if _n_ = 1 then do;
    declare hash sw(dataset:'stopwords');
    sw.definekey('word');
    sw.definedone();
  end;

  set raw_text;
  length clean $600 word prev $40 term $81 type $6;
  week = intnx('week.2', date, 0, 'b');              /* Monday-start weeks */
  format week date9.;

  clean = compress(lowcase(text), "'");             /* don't -> dont      */
  clean = prxchange('s/[^a-z]+/ /', -1, clean);      /* punctuation/digits -> space */

  prev = '';
  do i = 1 to countw(clean, ' ');
    word = scan(clean, i, ' ');
    if length(word) < &min_len then continue;
    if sw.check() = 0 then continue;                  /* stop word */

    term = word; type = 'word';   output;
    if prev ne '' then do;
      term = catx(' ', prev, word); type = 'phrase'; output;
    end;
    prev = word;
  end;
  keep id week term type;
run;

/*--------------------------------------------------------------------
  3. Weekly counts
--------------------------------------------------------------------*/
proc sql;
  create table week_docs as
  select intnx('week.2', date, 0, 'b') as week format=date9.,
         count(distinct id) as docs
  from raw_text
  group by 1
  order by 1;

  create table term_week as
  select term, type, week, count(distinct id) as docs_with
  from tokens
  group by term, type, week;
quit;

proc sql noprint;
  select max(week) into :last_week trimmed from week_docs;
quit;

/* NB: if the latest week is incomplete, that's fine - we use shares,
   not raw counts - but very small weeks are noisy */
data _null_;
  recent_start = intnx('week.2', &last_week, -(&recent_weeks - 1), 'b');
  base_start   = intnx('week.2', recent_start, -&baseline_weeks, 'b');
  call symputx('recent_start', recent_start);
  call symputx('base_start',   base_start);
  put 'Baseline from ' base_start date9. ' | Recent from ' recent_start date9.;
run;

/*--------------------------------------------------------------------
  4. Recent vs baseline - two-proportion z-test per term
--------------------------------------------------------------------*/
proc sql;
  create table period_docs as
  select sum(case when week >= &recent_start then docs else 0 end) as n1,
         sum(case when week >= &base_start and week < &recent_start
                  then docs else 0 end)                         as n0
  from week_docs;

  create table term_period as
  select term, type,
         sum(case when week >= &recent_start then docs_with else 0 end) as x1,
         sum(case when week >= &base_start and week < &recent_start
                  then docs_with else 0 end)                         as x0
  from term_week
  group by term, type;
quit;

data rising;
  if _n_ = 1 then set period_docs;
  set term_period;
  length flag $8;

  share_recent   = x1 / n1;
  share_baseline = x0 / n0;
  pooled = (x1 + x0) / (n1 + n0);
  if 0 < pooled < 1 then
    z = (share_recent - share_baseline) /
        sqrt(pooled*(1 - pooled)*(1/n1 + 1/n0));
  if x0 > 0 then lift = share_recent / share_baseline;

  if x1 >= &min_docs and z >= &z_cut then do;
    if x0 = 0 then flag = 'NEW';
    else           flag = 'RISING';
  end;
  else if x0 >= &min_docs and not missing(z) and z <= -&z_cut then flag = 'FALLING';

  format share_recent share_baseline percent8.1 z 6.1 lift 6.1;
run;

proc sort data=rising; by descending z; run;

title "Terms rising significantly (last &recent_weeks weeks vs previous &baseline_weeks)";
proc print data=rising noobs;
  where flag in ('NEW', 'RISING');
  var term type x1 share_recent x0 share_baseline lift z flag;
  label x1 = 'Recent mentions' x0 = 'Baseline mentions'
        share_recent = 'Recent share' share_baseline = 'Baseline share';
run;

title "Terms falling significantly";
proc print data=rising noobs;
  where flag = 'FALLING';
  var term type x1 share_recent x0 share_baseline z;
run;

/*--------------------------------------------------------------------
  5. Weekly trend chart for the top rising terms
     (fills in zero weeks so lines don't skip)
--------------------------------------------------------------------*/
data top_terms;
  set rising(where=(flag in ('NEW', 'RISING')));
  if _n_ > &top_n then stop;
  keep term;
run;

proc sql;
  create table trend as
  select t.term, w.week, w.docs,
         coalesce(c.docs_with, 0) as docs_with,
         calculated docs_with / w.docs as share format=percent8.1
  from top_terms t
       cross join week_docs w
       left join term_week c
         on c.term = t.term and c.week = w.week
  order by t.term, w.week;
quit;

title "Share of records mentioning each rising term, by week";
proc sgplot data=trend;
  series x=week y=share / group=term markers lineattrs=(thickness=2);
  refline &recent_start / axis=x lineattrs=(pattern=dash) label="Recent period";
  yaxis label="Share of records" grid;
  xaxis label="Week starting";
run;
title;

      Why rename?
      
The rest of the program stays the same

      
The mapping step renames your columns on the way in (for example received_dt becomes date). Every later step uses the names date, volume, id and text, so you only change the code in one place.

      
If you'd rather keep your own names everywhere, use EG's Find and Replace (Ctrl+H) on the whole program. That's riskier, because date appears in a lot of places.

    

    

      Common snag
      
Datetimes aren't dates

      
If your column holds a date and a time (for example 02NOV2026:09:15:00), convert it, or every row ends up in the wrong week:

      
date = datepart(created_dt);
format date date9.;

    

    

      Long comments
      
Make the text field long enough

      
If comments are longer than 300 characters, increase length text $300 to fit them. Then increase length clean $600 in the step that splits the text to match.

    

    

      Libraries
      
Point at your data

      
In EG, a table you can see in the Servers pane can usually be read as libref.table. Otherwise, add a libname statement at the top of the program to point at it.

Program 1 · Volume deviation monitor

  

    

      Settings at the top
      
Apply to every check

      

        
SettingDefaultAllowed valuesWhat it does

        
          
k2Any number, decimals allowedHow many standard deviations from normal counts as unusual. At 2 it's sensitive: about 1 normal period in 20 gets flagged. 2.5 is a middle ground. At 3 you only get strong signals: about 1 normal period in 370.

          
start_dateblankA date like 01JAN2025, or blankIgnore data before this date. The baseline is limited to this range too, so start about one baseline-length early.

      %volume_check( … )
      
Every argument

      

        
ArgumentIf left outAllowed valuesWhat it does

        
          
period=requiredDAY WEEK MONTH ALL, or a list such as DAY | WEEK. DAILY, WEEKLY and MONTHLY also work.DAY: each Mon–Sat day against the same weekday, plus a check that Sundays are zero.
WEEK: Monday-to-Sunday weeks, labelled by the Monday.
MONTH: calendar months as an average per open day, so short months don't look low.
ALL: all three.

          
baseline=56D / 12W / 12MALL, or a number followed by D, W, M or Y, e.g. 90D 26W 12M 2Y. One value, or a list with one per period.How much earlier history counts as normal. ALL uses every earlier period, so the baseline grows over time. A span uses only that much history before each date and rolls forward with it. A list such as 90D | 26W | 12M matches the periods in order.

          
views=ALLALL and/or your column names, separated by |. Put two names in one view to combine them: product channel.Which splits to check. Each view has its own baseline for every group in it. ALL | product | channel | product channel runs all four.

          
min_obs=4 / 6 / 6A whole number of 3 or more. One value, or one per period: 4 | 6 | 6How many earlier periods a baseline needs before anything can be flagged. Until then the period shows WARMUP.

          
charts=YY or NA chart for each group: volume against the shaded expected range, with markers on flagged periods.

          
tables=YY or NA full table of every period, with HIGH rows in red, LOW rows in purple and WARMUP rows greyed out.

        
      

      
The key observations table (flagged periods, worst first) is always printed. Run %flag_summary; once at the end, with no arguments, for every call-out from the run.

    


    

      Examples
      
Copy, paste, adjust

      
/* Day, week and month with default baselines, totals only */
%volume_check(period=ALL);

/* All three, each compared with all earlier history */
%volume_check(period=ALL, baseline=ALL);

/* Every period and every view */
%volume_check(period=ALL, baseline=90D | 26W | 12M,
              views=ALL | product | channel | product channel);

/* Daily by product, no charts */
%volume_check(period=DAY, baseline=90D, views=product, charts=N);

/* Weeks and months vs all history, 8 periods needed before flagging */
%volume_check(period=WEEK | MONTH, baseline=ALL, tables=N, min_obs=8);

/* Always finish with */
%flag_summary;
