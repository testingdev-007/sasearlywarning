SAS Early Warning Toolkit

Two SAS programs that spot trouble early. One flags days and weeks when volumes move unusually far from normal. The other finds the words people suddenly start using in free-text comments.

Before you start

Runs on

Base SAS only

It doesn't use SAS/ETS, Text Miner or Visual Text Analytics. All it needs is DATA steps, PROC SQL, PROC SORT, PROC PRINT and PROC SGPLOT, which any standard SAS 9.4 install has.

In Enterprise Guide

Run it as a program

  1. Choose File → New → Program.
  2. Paste in one of the programs below.
  3. Press F3 or click Run. The flagged days, weeks or terms appear under Results and the charts under Results/Graphs.
Try first

Sample data is built in

Each program starts by making fake data with known problems planted in it. Run it unchanged first to see what the flags look like, then swap in your own data (section 3).

01

Volume deviation monitor

For each day (or week), the program works out what normal looks like from recent history, then flags anything more than k standard deviations away from it.

The idea

A rolling expected range

The shaded band is the mean ± k SD of the previous periods. The current day isn't part of its own baseline, so a spike can't raise the bar it's measured against.

HIGHLOWOKWARMUP WARMUP means there isn't enough history to judge yet.
Weekdays

Mondays vs Mondays

Mon–Sat each get their own baseline: the last 8 of the same weekday. A quiet Saturday is judged against other Saturdays, so it isn't flagged LOW for being lower than a Tuesday.

Sundays

Should be zero

Every past Sunday is 0, so the SD is 0 and the standard deviation check can't work on them. Instead, any Sunday with volume above 0 is flagged SUNDAY and listed in its own report.

Bank holidays

Taken out of the check

Dates in the holidays table are left out, so a closed Monday isn't flagged LOW and doesn't drag down the baseline for later Mondays. Add your own closure days to it.

Weekly view

Weeks start on Monday

Daily volumes are added up into Monday-to-Sunday weeks with intnx('week.2', …), then checked against the previous 12 weeks. Every week has a weekend, so no adjustment is needed.

Settings

Choices at the top of the program

SettingDefaultWhat it changes
k2How far from normal counts as unusual. At 2, about 1 normal day in 20 is flagged. At 3, very few normal days are flagged, so the flags are more likely to be real problems.
window28 / 8 / 12How many previous periods make up the baseline: days, same-weekdays or weeks.
min_obs14 / 4 / 6How much history is needed before anything is flagged.
by=dowGives each group its own baseline. Use it for day of week, team or product.
Good to know

When volumes shift for good

If volumes permanently go up or down, you'll get a run of flags until the look-back window catches up. That's usually useful, because the run itself tells you something changed.

Output

What you get

  • A list of flagged days, with mean, SD and z-score
  • A list of flagged weeks
  • A list of Sundays with activity
  • A chart of volume against the shaded expected range

volume_deviation_flags.sas

191 lines · paste into a new EG program
/*====================================================================
  Volume deviation monitor
  Flags days/weeks where volume is more than K standard deviations
  from the rolling mean of the previous WINDOW periods.
  Base SAS only (no SAS/ETS needed). Runs as-is in SAS OnDemand / Viya.
====================================================================*/

%let k       = 2;    /* how many SDs counts as unusual (2 = ~5%, 3 = ~0.3%) */
%let window  = 28;   /* look-back periods for the baseline                  */
%let min_obs = 14;   /* don't flag until the baseline has this many points  */

/*--------------------------------------------------------------------
  0. SAMPLE DATA - replace with your own table (one row per record
     or per day, with a DATE and a VOLUME column)
--------------------------------------------------------------------*/
data raw;
  call streaminit(42);
  do date = '01JAN2026'd to '30JUN2026'd;
    select (weekday(date));                      /* 1=Sun ... 7=Sat */
      when (1)    volume = 0;                    /* Sunday: closed  */
      when (7)    volume = round(rand('normal', 300, 40));   /* quiet Saturday */
      otherwise   volume = round(rand('normal', 1000, 80));
    end;
    if date = '15MAR2026'd then volume = 40;     /* planted Sunday activity */
    if date = '17MAR2026'd then volume = 1600;   /* planted spike */
    if date = '02MAY2026'd then volume = 500;    /* planted drop  */
    output;
  end;
  format date date9.;
run;

/*--------------------------------------------------------------------
  1. Daily and weekly totals
--------------------------------------------------------------------*/
proc sql;
  create table daily as
  select date, sum(volume) as volume
  from raw
  group by date
  order by date;

  create table weekly as
  select intnx('week.2', date, 0, 'b') as week_start format=date9.,  /* Monday-start weeks */
         sum(volume) as volume
  from raw
  group by 1
  order by 1;
quit;

/* the flag macro expects a column called DATE */
data weekly; set weekly(rename=(week_start=date)); run;



/*--------------------------------------------------------------------
  2. Flagging macro
     Baseline uses ONLY previous periods, so today's value can't
     hide itself by inflating its own mean/SD.
     Optional BY= runs a separate baseline per group
     (e.g. per team, per product, or per day-of-week).
--------------------------------------------------------------------*/
%macro flag_deviations(in=, out=, window=&window, k=&k, min_obs=&min_obs, by=);

  proc sort data=&in out=_srt; by &by date; run;

  data &out;
    set _srt;
    by &by date;
    length flag $6;
    array buf[&window] _temporary_;   /* ring buffer of previous values */
    retain n 0;

    %if %length(&by) %then %do;
      if first.%scan(&by, -1) then do;
        call missing(of buf[*]);
        n = 0;
      end;
    %end;

    /* stats over the previous WINDOW values */
    cnt = 0; s = 0; ss = 0;
    do i = 1 to &window;
      if not missing(buf[i]) then do;
        cnt = cnt + 1;
        s   = s + buf[i];
        ss  = ss + buf[i]**2;
      end;
    end;

    if cnt >= &min_obs then do;
      mean  = s / cnt;
      sd    = sqrt(max(0, (ss - cnt*mean**2) / (cnt - 1)));
      lower = mean - &k*sd;
      upper = mean + &k*sd;
      if sd > 0 then z = (volume - mean) / sd;
      if      volume > upper then flag = 'HIGH';
      else if volume < lower then flag = 'LOW';
      else                        flag = 'OK';
    end;
    else flag = 'WARMUP';

    /* add this period to the buffer for future rows */
    n = n + 1;
    buf[mod(n-1, &window) + 1] = volume;

    format mean sd lower upper comma12.1 z 6.2;
    drop i s ss n;
  run;

%mend flag_deviations;

/*--------------------------------------------------------------------
  3. Run it
--------------------------------------------------------------------*/
/* Bank holidays / closure days - excluded from the daily check so they
   don't get flagged LOW or drag the baseline down. Add your own dates. */
data holidays;
  input date :date9.;
  format date date9.;
  datalines;
03APR2026
06APR2026
04MAY2026
25MAY2026
;
run;

/* Split days: Sundays get a simple "should be zero" check,
   Mon-Sat each get their own baseline (Mondays vs previous Mondays...) */
proc sql;
  create table daily_dow as
  select d.*, weekday(d.date) as dow
  from daily d
  where d.date not in (select date from holidays);
quit;

data sunday_check open_days;
  set daily_dow;
  if dow = 1 then output sunday_check;
  else output open_days;
run;

data sunday_check;
  set sunday_check;
  length flag $6;
  if volume > 0 then flag = 'SUNDAY';   /* any Sunday activity is worth a look */
  else flag = 'OK';
run;

/* Daily (Mon-Sat): last 8 of the same weekday as baseline */
%flag_deviations(in=open_days, out=daily_flags, window=8, min_obs=4, by=dow);
proc sort data=daily_flags; by date; run;

/* Weekly: last 12 weeks as baseline (every week has a weekend, so no
   adjustment needed - but a bank-holiday week will read lower) */
%flag_deviations(in=weekly, out=weekly_flags, window=12, min_obs=6);

/*--------------------------------------------------------------------
  4. Exceptions report
--------------------------------------------------------------------*/
title "Daily volumes outside &k SD of the rolling baseline";
proc print data=daily_flags noobs;
  where flag in ('HIGH', 'LOW');
  var date volume mean sd z flag;
run;

title "Sundays with any volume";
proc print data=sunday_check noobs;
  where flag = 'SUNDAY';
  var date volume flag;
run;

title "Weekly volumes outside &k SD of the rolling baseline";
proc print data=weekly_flags noobs;
  where flag in ('HIGH', 'LOW');
  var date volume mean sd z flag;
run;

/*--------------------------------------------------------------------
  5. Control-chart style plot
--------------------------------------------------------------------*/
title "Daily volume with &k SD band";
proc sgplot data=daily_flags;
  band   x=date lower=lower upper=upper / transparency=0.7 legendlabel="Expected range";
  series x=date y=mean   / lineattrs=(pattern=dash) legendlabel="Rolling mean";
  series x=date y=volume / legendlabel="Volume";
  scatter x=date y=volume / group=flag markerattrs=(symbol=circlefilled size=9);
  where flag ne 'WARMUP';
  yaxis label="Volume";
run;
title;
02

Rising keywords in free text

The program splits comments into words and two-word phrases and removes stop words. It then compares how often each term appears in the last 4 weeks with the 12 weeks before, and flags the ones that have gone up significantly.

Step 1

Clean and split the text

The text is made lowercase and stripped of punctuation and numbers. Stop words are removed, then the words that are left are paired up into phrases.

"My card was declined!"→ carddeclinedcard declined

Phrases are paired up after stop words are removed, so "card was declined" becomes the phrase "card declined".

Step 2

Count comments, not words

Each week, it counts how many comments mention a term and works that out as a share of all comments that week. One long rant can't push a word up, and a busy week doesn't make every word look like it's rising.

Step 3

Recent vs baseline

A two-proportion z-test asks whether the recent share is really higher than the baseline share, or just chance.

z = (precent − pbase) / √( p(1−p)(1/nrecent + 1/nbase) )
Step 4

Flag and chart

NEWnot seen in the baseline at all
RISINGsignificantly more common, with a lift such as 3.2×
FALLINGsignificantly less common

The top rising terms are charted week by week, with a dashed line where the recent period starts.

Settings

Choices at the top of the program

SettingDefaultWhat it changes
recent_weeks4How many weeks count as "now".
baseline_weeks12How many weeks before that count as normal.
z_cut3The significance bar. You're testing thousands of terms at once, so a bar of 2 flags plenty by pure chance.
min_docs10The fewest recent mentions a term needs before it can be flagged. Stops one-off typos showing up as trends.
min_len3Drops very short tokens.
top_n6How many rising terms the chart shows.
Tune this first

Add your own stop words

Words that appear in nearly every comment in your data, such as customer, account, bank, complaint, please, will take up space in the results. Add them to the stopwords list.

"not" and "no" are deliberately kept, because "not arrived" carries meaning.

Known limit

Word forms are counted separately

"crash", "crashed" and "crashing" are three different words to this program. If that splits a signal, a small lookup table that maps word forms to one root fixes it.

Partial weeks

Shares, not counts

Because it compares shares, an unfinished current week won't look like a drop. But a week with very few comments will give noisy results.

rising_keywords.sas

226 lines · paste into a new EG program
/*====================================================================
  Rising keywords in free text
  1. Clean + tokenise text into words (and two-word phrases)
  2. Remove stop words
  3. Count how many RECORDS mention each term per week
     (document frequency - one long rant can't dominate)
  4. Compare the share of records mentioning each term in the RECENT
     period vs a BASELINE period (two-proportion z-test)
  5. Report and chart the terms that are rising significantly
  Base SAS only. Runs as-is with the sample data.
====================================================================*/

%let recent_weeks   = 4;    /* the "now" period                           */
%let baseline_weeks = 12;   /* the "normal" period just before it         */
%let min_docs       = 10;   /* ignore terms with fewer recent mentions    */
%let z_cut          = 3;    /* significance bar - keep high, you're testing
                               thousands of terms so 2 gives lots of noise */
%let min_len        = 3;    /* drop very short tokens                     */
%let top_n          = 6;    /* terms to chart                             */

/*--------------------------------------------------------------------
  0. SAMPLE DATA - replace with your table: ID, DATE, TEXT
     (a new login problem appears from June)
--------------------------------------------------------------------*/
data raw_text;
  call streaminit(7);
  length text $300;
  array p[8] $80 _temporary_ (
    "My card was declined at the shop",
    "The app keeps crashing when I open it",
    "Waiting too long on the phone for help",
    "Charged a fee I did not expect",
    "Transfer has not arrived after three days",
    "Staff were rude and unhelpful in branch",
    "Statement shows a payment I don't recognise",
    "Interest rate changed without any notice");
  do date = '01JAN2026'd to '30JUN2026'd;
    if weekday(date) = 1 then continue;              /* closed Sundays */
    n = 20 + ceil(20*rand('uniform'));
    do j = 1 to n;
      text = p[ceil(8*rand('uniform'))];
      if date >= '01JUN2026'd and rand('uniform') < 0.25 then
        text = "Since the app update it logs me out and Face ID login fails!";
      id + 1;
      output;
    end;
  end;
  format date date9.;
  keep id date text;
run;

/*--------------------------------------------------------------------
  1. Stop words - extend with words that are everywhere in YOUR data
     (e.g. customer, bank, account, complaint, please)
     'not' / 'no' are deliberately kept: "not arrived" matters.
--------------------------------------------------------------------*/
data stopwords;
  length word $40;
  input word $ @@;
  datalines;
a about above after again against all also am an and any are as at be
because been before being below between both but by can could did do does
doing down during each few for from further had has have having he her here
hers herself him himself his how i if in into is it its itself just me more
most my myself nor of off on once only or other our ours ourselves out over
own same she should so some such than that the their theirs them themselves
then there these they this those through to too under until up very was we
were what when where which while who whom why will with would you your yours
yourself yourselves dont didnt doesnt cant wont im ive its get got been
since it they them
;
run;

proc sort data=stopwords nodupkey; by word; run;

/*--------------------------------------------------------------------
  2. Tokenise: one row per record per term (words + two-word phrases)
--------------------------------------------------------------------*/
data tokens;
  if _n_ = 1 then do;
    declare hash sw(dataset:'stopwords');
    sw.definekey('word');
    sw.definedone();
  end;

  set raw_text;
  length clean $600 word prev $40 term $81 type $6;
  week = intnx('week.2', date, 0, 'b');              /* Monday-start weeks */
  format week date9.;

  clean = compress(lowcase(text), "'");             /* don't -> dont      */
  clean = prxchange('s/[^a-z]+/ /', -1, clean);      /* punctuation/digits -> space */

  prev = '';
  do i = 1 to countw(clean, ' ');
    word = scan(clean, i, ' ');
    if length(word) < &min_len then continue;
    if sw.check() = 0 then continue;                  /* stop word */

    term = word; type = 'word';   output;
    if prev ne '' then do;
      term = catx(' ', prev, word); type = 'phrase'; output;
    end;
    prev = word;
  end;
  keep id week term type;
run;

/*--------------------------------------------------------------------
  3. Weekly counts
--------------------------------------------------------------------*/
proc sql;
  create table week_docs as
  select intnx('week.2', date, 0, 'b') as week format=date9.,
         count(distinct id) as docs
  from raw_text
  group by 1
  order by 1;

  create table term_week as
  select term, type, week, count(distinct id) as docs_with
  from tokens
  group by term, type, week;
quit;

proc sql noprint;
  select max(week) into :last_week trimmed from week_docs;
quit;

/* NB: if the latest week is incomplete, that's fine - we use shares,
   not raw counts - but very small weeks are noisy */
data _null_;
  recent_start = intnx('week.2', &last_week, -(&recent_weeks - 1), 'b');
  base_start   = intnx('week.2', recent_start, -&baseline_weeks, 'b');
  call symputx('recent_start', recent_start);
  call symputx('base_start',   base_start);
  put 'Baseline from ' base_start date9. ' | Recent from ' recent_start date9.;
run;

/*--------------------------------------------------------------------
  4. Recent vs baseline - two-proportion z-test per term
--------------------------------------------------------------------*/
proc sql;
  create table period_docs as
  select sum(case when week >= &recent_start then docs else 0 end) as n1,
         sum(case when week >= &base_start and week < &recent_start
                  then docs else 0 end)                         as n0
  from week_docs;

  create table term_period as
  select term, type,
         sum(case when week >= &recent_start then docs_with else 0 end) as x1,
         sum(case when week >= &base_start and week < &recent_start
                  then docs_with else 0 end)                         as x0
  from term_week
  group by term, type;
quit;

data rising;
  if _n_ = 1 then set period_docs;
  set term_period;
  length flag $8;

  share_recent   = x1 / n1;
  share_baseline = x0 / n0;
  pooled = (x1 + x0) / (n1 + n0);
  if 0 < pooled < 1 then
    z = (share_recent - share_baseline) /
        sqrt(pooled*(1 - pooled)*(1/n1 + 1/n0));
  if x0 > 0 then lift = share_recent / share_baseline;

  if x1 >= &min_docs and z >= &z_cut then do;
    if x0 = 0 then flag = 'NEW';
    else           flag = 'RISING';
  end;
  else if x0 >= &min_docs and not missing(z) and z <= -&z_cut then flag = 'FALLING';

  format share_recent share_baseline percent8.1 z 6.1 lift 6.1;
run;

proc sort data=rising; by descending z; run;

title "Terms rising significantly (last &recent_weeks weeks vs previous &baseline_weeks)";
proc print data=rising noobs;
  where flag in ('NEW', 'RISING');
  var term type x1 share_recent x0 share_baseline lift z flag;
  label x1 = 'Recent mentions' x0 = 'Baseline mentions'
        share_recent = 'Recent share' share_baseline = 'Baseline share';
run;

title "Terms falling significantly";
proc print data=rising noobs;
  where flag = 'FALLING';
  var term type x1 share_recent x0 share_baseline z;
run;

/*--------------------------------------------------------------------
  5. Weekly trend chart for the top rising terms
     (fills in zero weeks so lines don't skip)
--------------------------------------------------------------------*/
data top_terms;
  set rising(where=(flag in ('NEW', 'RISING')));
  if _n_ > &top_n then stop;
  keep term;
run;

proc sql;
  create table trend as
  select t.term, w.week, w.docs,
         coalesce(c.docs_with, 0) as docs_with,
         calculated docs_with / w.docs as share format=percent8.1
  from top_terms t
       cross join week_docs w
       left join term_week c
         on c.term = t.term and c.week = w.week
  order by t.term, w.week;
quit;

title "Share of records mentioning each rising term, by week";
proc sgplot data=trend;
  series x=week y=share / group=term markers lineattrs=(thickness=2);
  refline &recent_start / axis=x lineattrs=(pattern=dash) label="Recent period";
  yaxis label="Share of records" grid;
  xaxis label="Week starting";
run;
title;

Plug in your data

Each program starts with a sample-data step. Swap it for a step that reads your table and renames your columns to the names the program uses. Nothing else in the program needs to change.

Step 1

Find your column names and types

Run this in EG on your source table. It lists each column's name, whether it's Num or Char, and its format.

proc contents data=mylib.complaints varnum;
run;

The format tells you what kind of date you have: DATE9. or DDMMYY10. means a date, DATETIME20. means a date and time, and a Char column means the date is stored as text.

      Why rename?
      
The rest of the program stays the same

      
The mapping step renames your columns on the way in (for example received_dt becomes date). Every later step uses the names date, volume, id and text, so you only change the code in one place.

      
If you'd rather keep your own names everywhere, use EG's Find and Replace (Ctrl+H) on the whole program. That's riskier, because date appears in a lot of places.

    

    

      Common snag
      
Datetimes aren't dates

      
If your column holds a date and a time (for example 02NOV2026:09:15:00), convert it, or every row ends up in the wrong week:

      
date = datepart(created_dt);
format date date9.;

    

    

      Long comments
      
Make the text field long enough

      
If comments are longer than 300 characters, increase length text $300 to fit them. Then increase length clean $600 in the step that splits the text to match.

    

    

      Libraries
      
Point at your data

      
In EG, a table you can see in the Servers pane can usually be read as libref.table. Otherwise, add a libname statement at the top of the program to point at it.
